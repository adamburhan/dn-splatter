# Bimodal Depth Supervision — Complete Project Account

Everything done on 2026-08-27/28: what ran, what exists where, what is assumed,
how to reproduce, and what separates the current result from a convincing paper.
Companion docs: `dnsplatter_map.md` (repo recon), `dnsplatter_killtest.md`
(phase-1 diagnostic), `bimodal_ablation.md` (phase-2 ablation + verdict).

## 1. What was done, in order

**Phase 0 — recon (read-only).** Mapped DN-Splatter's loss surface (file:line in
`dnsplatter_map.md`). Key discoveries that shaped everything: the default
EdgeAwareLogL1 downweights by *RGB* gradients with max attenuation e⁻¹ (so it is
~inert at depth edges); the depth term enters as (1+λ)·loss, so λ=0.2 means
weight 1.2 ≈ the RGB loss; an inverse-depth Laplacian edge detector already
exists in the repo but only masks the AGS-Mesh *normal* loss. Literature check
(web): two-surface-hypothesis supervision of rendered depth is unpublished;
closest are SCADE (CVPR'23, global cIMLE hypotheses, NeRF termination samples —
must cite/differentiate), SMD-Nets, TWISE, arXiv:2606.02552 (bimodal fg/bg
representations, estimator-side only).

**Phase 1 — pre-registered kill tests (T1.1/T1.2/T1.3).**
- Data: ScanNet++ was unavailable (no token anywhere reachable) → MuSHRoom
  (koivu, coffee_room, vr_room; iPhone captures, 994×738, ARKit sensor depth,
  Zoe mono prior generated by the repo's own pipeline, Faro laser reference
  depth for ~95% of long-capture frames).
- T1.1 exposure: 1.3–2.7% of supervised pixels in a strict 2px depth-edge band;
  but **9–14% of depth-loss mass** (sensor prior). EdgeAware weighting removes
  ~2% of band loss → experimentally inert.
- T1.2 gap/noise: band prior error 5.1–17.5× off-band (strict defs), monotone in
  local fg/bg contrast, error ≈ ½ the local gap; 26–50% of band pixels are
  flying pixels; prior edges misplaced 2–8px vs GT edges.
- T1.3 attribution: trained EdgeAwareLogL1 / plain L1 / no-depth per scene (9
  runs, 30k steps). Unimodal is WORSE than no-depth on band RGB (3/3 scenes,
  ~1dB, band-concentrated), depth benefit collapses in-band (1.1–1.4× vs
  2.4–4.6× off-band), EdgeAware ≡ L1 within noise, artifacts = silhouette halos.
- Verdict: borderline branch (exposure narrow, severity extreme) → proceed to
  implementation with masking as the declared true competitor.

**Phase 2 — implementation + four-arm ablation.**
- `hyp_extract.py`: per-frame band + two-surface hypotheses (d_fg/d_bg = p90/p10
  of inverse depth in a 21px window; WIN tuned on koivu only via GT-coverage
  sweep {13,17,21} → 54.3% coverage / 0.098m min-err vs unimodal's 18.8%/0.448m)
  + degenerate gate. Validated: synthetic step-edge recovered exactly, flying
  pixels rejected, overlays straddle silhouettes, pixel-aligned through the real
  dataloader (1.47% band px).
- New losses in the repo: `BimodalLogL1` (min over hypotheses in active band,
  unimodal elsewhere) and `MaskedLogL1` (unimodal, zeroed in-band), identical
  sum/N_valid normalization and (1+λ) handling. Loss-descent unit test: band
  pixels snap from the phantom middle to a plateau; masked leaks zero band
  gradient.
- Arms: `logl1` / `masked` / `bimodal` retrained per scene (9 runs), `nodepth`
  reused from phase 1 (bit-identical config). Renders → band-sliced eval with
  two NEW output-side metrics (wrong-commitment and phantom-middle rates,
  defined from *GT* local surfaces) → mesh export (gs-mesh `dn`) → MuSHRoom
  vis-cull mesh eval + GT-edge boundary slicing (5cm radius, GT-anchored labels).
- **Verdict (pre-registered rule, reporting scenes coffee_room + vr_room): PASS.**
  Bimodal vs masked: band depth error −25%/−22%, boundary mesh F1 +0.011/+0.022,
  band RGB within noise, wrong-commit elevated (+0.05–0.06) but wins intact;
  phantom-middle lowest of all arms (below even nodepth) in 3/3 scenes; best
  full-image PSNR among depth-supervised arms 3/3. Per-frame vs published
  baseline: bimodal wins 90/106 long-capture views, mean +0.29dB, +2.97dB max
  win vs −0.45dB max loss.

## 2. Exact configuration of every training arm

All runs: `ns-train dn-splatter` at repo commit `97588b4` + our patches,
30k iterations, `--timestamp run1`, `--vis tensorboard`, MuSHRoom dataparser
`--mode iphone` (depth_mode=sensor default), and the common flags:

```
--pipeline.model.use-depth-smooth-loss True
--pipeline.model.use-normal-loss True
--pipeline.model.normal-supervision mono
```

| arm | depth flags |
|---|---|
| edgeaware (phase 1) | `use-depth-loss True, depth-loss-type EdgeAwareLogL1, depth-lambda 0.2` |
| l1 (phase 1) | `... depth-loss-type L1 ...` |
| logl1 | `... depth-loss-type LogL1 ...` |
| masked | `... depth-loss-type MaskedLogL1 ...` |
| bimodal | `... depth-loss-type BimodalLogL1 ...` |
| nodepth | `use-depth-loss False` |

Everything else = repo defaults (`dn_config.py` dn-splatter method: splatfacto
optimizers, stop_split 15k, normal λ 0.1, smooth TV λ 0.1, camera-opt off).
Single seed per arm (nerfstudio default seeding). ~1.5–2h per run on one RTX PRO
6000 Blackwell. Launcher: `killtest/train_baseline.sh` (arms are literally these
case branches); queues in `killtest/run_queue.sh`.

Kill-test thresholds: ALL in `killtest/kt_config.py` (band defs and widths,
validity range, contrast window/percentiles, flying-pixel margin, WIN sweep,
degenerate gate, commit tolerance). Per-scene extraction configs are dumped to
`bimodal_hyp/extract_config.json` next to the data.

## 4. Implicit assumptions (the honest list)

Data & ground truth:
1. **MuSHRoom stands in for the target domain** (originally ScanNet++). Only
   ARKit **sensor** depth was used as the supervising prior in trainings; the
   mono (Zoe) prior was measured in the diagnostic (T1.1/T1.2) but never trained
   against.
2. **Faro reference depth = GT.** It is a rendering of the laser scan under
   ICP-aligned poses; occlusion boundaries inherit pose/ICP error. We exclude
   invalid GT pixels, and off-band prior error (1.4–4.3cm) bounds the global
   alignment error, but part of the measured 2–8px edge offset may be GT's, not
   the prior's. Band metrics near edges carry this contamination in ALL arms
   equally.
3. **Eval views are trajectory-interpolating** (every ~10th long-capture frame).
   Headline tables exclude the short-capture (cross-trajectory) views; those are
   where per-patch differences are largest (qualitative only, so far).

Method:
4. Band = grad_logd > 0.1, 2px dilation — one config carried through phase 2
   (diagnostic checked 3 defs × 2 widths, the ablation did not).
5. Hypotheses = p10/p90 of inverse depth in WIN=21 — WIN tuned on koivu only;
   percentile choice (vs mode-finding/clustering) untested.
6. Degenerate gate thresholds (0.1m / 5%) inherited from the diagnostic.
7. The (1+λ) quirk and sum/N_valid normalization are held identical across arms
   — internally consistent, but absolute loss weight differs from a "clean"
   λ·loss implementation.
8. **Expected-depth rendering**: both the loss and the eval use gsplat's
   alpha-blended (expected) depth, which *cannot* represent a discontinuity
   sharply even in principle. A median-depth formulation might interact
   differently with the bimodal loss. Unexamined.

Experiment:
9. **Single seed per arm.** Direction-consistency across 3 scenes and ~5 metrics
   is the current evidence of signal; no variance estimates. Margins of
   ~0.01 mesh F1 / 0.2dB individually are within plausible seed noise.
10. nodepth reused from phase 1 (flags verified identical; same commit/env).
11. Environment: torch 2.7.1+cu128 on Blackwell (sm_120), gsplat 1.0.0 source
    build — NOT the pixi env the authors published. Baseline reproduces
    paper-ballpark MuSHRoom numbers, taken as evidence of faithfulness.
12. Mesh protocol: one exporter (DepthAndNormalMapsPoisson, poisson depth 9),
    the repo's vis-cull protocol, boundary = 5cm around GT-edge backprojections,
    GT-anchored slice labels, 500k samples. Not checked against TSDF/SuGaR
    exporters.
13. Band-sliced LPIPS uses lpips(spatial=True) map averaging; band SSIM uses a
    uniform 11px window map — both nonstandard (but arm-symmetric) usages.

```bash
conda create -n dnsplat python=3.10 -y && conda activate dnsplat
pip install "numpy<2" && pip install torch==2.7.1 torchvision==0.22.1 --index-url https://download.pytorch.org/whl/cu128
export CUDA_HOME=/usr/local/cuda-12.8 PATH=$CUDA_HOME/bin:$PATH TORCH_CUDA_ARCH_LIST=12.0
pip install ninja wheel && pip install gsplat==1.0.0 --no-build-isolation
pip install nerfstudio==1.1.3 && pip install "numpy<2"
cd dn-splatter && pip install -e . --no-deps
pip install natsort pytorch-lightning geffnet pyrender pymeshlab omnidata-tools scipy lpips
# gotchas: torch>=2.6 weights_only (patched in normals_from_pretrain.py; export
# TORCH_FORCE_NO_WEIGHTS_ONLY_LOAD=1 for render/eval); gsplat JIT needs nvcc in
# PATH at *every* import; first-ever import races if two procs start together.

# 2. Data (per scene: koivu coffee_room vr_room)
wget https://zenodo.org/records/10230733/files/<room>_iphone.tar.gz   # + extract
wget https://zenodo.org/records/10222321/files/<room>_mesh_pd.tar.gz  # gt mesh
wget https://zenodo.org/records/10438963/files/reference_depth.tar.gz # faro depth
python dn_splatter/data/download_scripts/download_omnidata.py         # normals ckpt

# 3. One-time per-scene assets (auto-generated on first ns-train, or explicitly):
#    normals_from_pretrain (omnidata), iphone_pointcloud.ply, mono_depth (Zoe),
#    and OUR hypothesis maps:
cd killtest
python hyp_extract.py --selftest                       # must print SELFTEST_OK
python loss_tests.py --loss-descent                    # must print LOSS_DESCENT_OK
for cap in long_capture short_capture; do
  python hyp_extract.py --scene <room_dir> --capture $cap --source sensor
done
python loss_tests.py --dataloader --scene <room_dir>   # pixel-alignment check

# 4. Diagnostic measurements (optional, reproduces killtest tables)
python t11_exposure.py --scene <room_dir> --out t11.json
python t12_gap.py --scene <room_dir> --out t12.json

# 5. Trainings (per scene x arm; see train_baseline.sh for exact flags)
./train_baseline.sh <room_dir> {edgeaware|l1|logl1|masked|bimodal|nodepth} <gpu>

# 6. Eval per arm

    --output-dir renders/<tag> --split eval
python t13_eval.py --render-dir renders/<tag> --scene <room_dir> --out t13.json
gs-mesh dn --load-config <run>/config.yml --output-dir meshes/<tag>
python mesh_boundary_eval.py --scene <room_dir> \
    --pred-mesh meshes/<tag>/DepthAndNormalMapsPoisson_poisson_mesh.ply --out mesh.json
python t13_panels.py --render-dirs renders/tagA renders/tagB ... --scene <room_dir> --out panels/
```

mesh/eval post-processing, on 2× RTX PRO 6000.

## 6. What's missing for a *convincing* positive result

Ordered by (impact ÷ cost); the first three are near-mandatory for a paper.

1. **Seed repeats (highest priority).** 3 seeds × {logl1, masked, bimodal} × 3
   scenes = 27 runs (~2 days on snoopy, ~2h wall on a cluster). The
   bimodal-vs-masked margins (0.01–0.02 F1, 0.02–0.03m derr) need error bars to
   survive review. This is exactly the Mila batch-job use case.
2. **Quantify the short-capture (cross-trajectory) eval.** Faro reference depth
   exists for short captures too; the largest observed differences (patch errors
   4× lower) are there and currently only qualitative. Likely turns the modest
   headline margins into the paper's strongest table. Cost: eval-only, hours.
3. **Band-width / misplacement sensitivity.** Run masked-4px and bimodal-4px on
   one scene (koivu, where 6–8px misplacement beat the 2px band): shows (a)
   whether wider masking closes the gap to bimodal (must survive this!) and (b)
   whether bimodal-4px recovers koivu's residual band RGB harm. 4–6 runs.
4. **Mono-prior replication (phase-2 plan as written).** 4 arms × 3 scenes with
   the Zoe prior + window_contrast band. Expected stronger effect (T1.2: mono is
   worse at edges, 26–50% fly). Makes the claim prior-general. 9–12 runs.
5. **Second dataset.** ScanNet++ (needs your token; the dataparser + our loaders
   already support it modulo the mono/sensor path) or Replica (synthetic, clean
   GT — good for a controlled table). Makes the claim dataset-general.
6. **One external baseline** beyond internal arms — e.g. depth-loss uncertainty
   weighting or DET-GS-style edge masking — so "masked" isn't the only
   competitor we constructed ourselves. (EdgeAware≡L1 is already a nice
   published-baseline takedown, keep it prominent.)
7. **Soft mixture variant** (side-mass-weighted NLL instead of hard min): the
   obvious reviewer ask given the +0.05 wrong-commitment; even a 1-scene
   demonstration defuses it.
8. Robustness checks, cheap: second mesh exporter (TSDF) on one scene; report
   median-depth rendering at eval; grad_logd threshold ±(0.05/0.2) sensitivity
   on the diagnostic tables (data already cached, eval-only).
9. **Writing assets**: the mechanism figure (T1.2 contrast-monotone curve +
   fly-pixel fraction), the loss-mass argument, depthcrop figures (koivu 00142 /
   00197 phantom membranes), mesh close-ups at those walls (not yet rendered),
   and the pre-registration story itself — a reviewer-friendly framing that the
   decision rule was written before any training.

**Paper skeleton that the evidence currently supports:** (i) diagnosis: unimodal
depth supervision at prior depth edges is *actively harmful* — pre-registered,
causal (vs no-depth control), fingerprinted (contrast-monotone, fly-pixels),
metric-blind (RGB metrics barely see it; depth/mesh do); (ii) the published
edge-aware mitigation is provably inert; (iii) trivial band-masking recovers
most of the harm — itself a useful practitioner finding; (iv) two-hypothesis
supervision strictly dominates masking (band geometry −25%, boundary mesh,
phantom-middle below even the unsupervised control) at the cost of a measured,
bounded wrong-commitment rate. The honest title is closer to "diagnosing and
fixing depth supervision at discontinuities in 3DGS" than "a new loss beats
SOTA" — the diagnostic is as much of the contribution as the loss.
